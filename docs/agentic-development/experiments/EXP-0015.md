## Static wildcard finding (maintainer-supplied)

The current allows in the `nudge-audit.md` harness include:

- `git diff --name-status *`
- `git diff --check *`
- `git ls-files *`

These three rules are broader than their apparent path-scoped purpose because the trailing `*` matches any additional argument, including enumeration-style arguments such as `--ignored`, `--others`, `HEAD`, `--cached`, or arbitrary repository paths.

### Official wildcard semantics (maintainer-supplied facts)

- `*` matches zero or more characters.
- `?` matches exactly one character.
- All other characters, including spaces, match literally.
- The last matching rule wins.

### Why the current allows are too broad

Under the official semantics, the literal-space distinction governs each pattern:

- `git diff --name-status *` requires the literal prefix `git diff --name-status `, including its trailing space, followed by zero or more characters. It therefore does not match bare `git diff --name-status` (which has no trailing space), but it does match argument-bearing forms such as `git diff --name-status HEAD` and `git diff --name-status --cached`.
- The same literal-space distinction applies to `git diff --check *`: it requires the literal prefix `git diff --check ` followed by zero or more characters, does not match bare `git diff --check`, and does match `git diff --check <anything>`.
- The same literal-space distinction applies to `git ls-files *`: it requires the literal prefix `git ls-files ` followed by zero or more characters, does not match bare `git ls-files`, and does match `git ls-files --ignored` and `git ls-files --others`.

The last matching rule wins, so the current allowlist effectively exposes a broad trailing-argument surface that the apparent path-scoped purpose did not intend.

## Accepted ordered permission rewrite (maintainer-supplied)

The accepted ordered replacement is:

```yaml
bash:
  "*": deny

  "git diff --name-status": allow
  "git diff --name-status *": deny
  "git diff --name-status -- *": allow

  "git diff --check": allow
  "git diff --check *": deny
  "git diff --check -- *": allow

  "git ls-files *": deny
  "git ls-files -- *": allow
```

The literal space before each trailing wildcard means the broad trailing-argument deny does not match its corresponding bare command (because the bare command has no trailing space).

The replacement:

- preserves bare `git diff --name-status`;
- preserves bare `git diff --check`;
- permits only explicit `-- <pathspec>` argument forms;
- denies `git diff --name-status HEAD`;
- denies `git diff --name-status --cached`;
- denies `git ls-files --ignored`;
- denies `git ls-files --others`;
- permits `git ls-files -- <pathspec>`.

No permission rewrite is applied in this Build.
