## Original B4c failure

The original B4c validation executed the full validator regression after the
five non-experiment Candidate-B paths had been materialized. The result was:

- Validator regression: `Ran 98 tests` and `FAILED (failures=45)`.

B4c correctly hard-stopped at that point. The failures were concentrated in
the validator test surface rather than in the Candidate-B synchronization
content itself.

## D1/D2/D3 diagnosis

The D1/D2/D3 diagnosis produced the following directly proven findings:

- **D1.** `tests/_helpers.py` copied the live contract but hard-coded stale
  active release-document roots and current Android fixture metadata,
  pinning the test surface to the inherited v0.1.1 release identity rather
  than the active v0.1.2 contract.
- **D2.** `tests/test_validator_repository.py` contained release-coupled
  v0.1.1 positive fixtures, negative fixtures, AGENTS fixtures, ProductScope
  charter header and path assertions, and related assertions that fixed the
  test expectations to the inherited v0.1.1 release identity.
- **D3.** `scripts/validate_local.py` had a release-neutral-path
  implementation but a production semantic defect for the zero Complete
  phases case. The expected display was `(no phases complete)` while the
  observed display was `(no completed-range claim)`, and the validator
  incorrectly compared those two display strings rather than comparing the
  underlying semantic completed-claim values.

## Corrective implementation

The corrective slice produced the following changes:

- **C1.** `tests/_helpers.py` became contract-driven, reading the active
  release identity and document roots from `scripts/release_contract.json`
  rather than hard-coding them.
- **C2a.** `scripts/validate_local.py` changed its completed-range
  presentation from a string comparison to a semantic completed-claim
  comparison, returning a `tuple[int, int] | None` for completed ranges
  and `None` for zero Complete phases. `None == None` now passes for zero
  Complete phases.
- **C2b1.** `tests/test_validator_repository.py` gained contract-derived
  fixture identity, positive repository fixtures, and early README tests.
  The C2b1 historical execution deviation is preserved in the
  Agent and harness observations section below.
- **C2b1-R1.** A subsequent retry directly verified the three edited
  methods that the original C2b1 post-edit readback had not surfaced, and
  accepted the C2b1 artifact.
- **C2b2a.** Six repository-consistency negative tests became
  release-neutral.
- **C2b2b.** ProductScope `CHARTER_HEADER` and charter-path lookup became
  contract-driven.
