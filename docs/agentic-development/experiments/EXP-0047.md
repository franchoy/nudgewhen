## 2. Objective and exact Phase 4 scope

Phase 4 owns the minimal Compose editing UX layered onto the existing `ReminderScreen` / `MainActivity` integration. ## 3. Frozen Phase 1 Compose editing contract

The Phase 1 architecture contract (frozen SHA-256 `71a8c56e3515a17ebfebd4bde42be90991caab7afeb8528ca4173eec3a0630c5`, exact-head CI `33183197545 / success`) recorded the bounded Compose editing semantics that Phase 4 was required to satisfy without altering:

- state owner: `ReminderScreen`;
- additional conceptual state: `editingId: String?`, `editBuffer: String`;
- derived conceptual active-editing identity: `activeEditingId`, defined only while a row is in editing row state; non-null by construction because Save is rendered / invoked only for the active editing row;
- ordinary `remember(controller)` state;
- no `rememberSaveable` solely for editing;
- at most one edit at a time;
- normal row: Text, Edit `TextButton`, Remove `TextButton`;
- editing row: `OutlinedTextField`, Save `TextButton`, Cancel `TextButton`;
- Edit: prefill buffer with current text; set `editingId`; entering edit for another reminder discards the previous unsaved buffer;
- Save: only for the active editing row; explicit non-null `activeEditingId` passed to `controller.edit(activeEditingId, editBuffer)`; only on normal return AND `accepted == true` does the row refresh `reminders` from `controller.reminders`, exit edit mode, and clear the edit buffer;
- `accepted == false`: remain editing; retain edit buffer; no success transition;
- `controller.edit` throws: no post-success UI transition; no swallowing solely for editing; do not clear edit state as though Save succeeded; detailed persistence-error UX remains outside v0.1.3;
- Cancel: no controller call; exit edit mode; clear edit buffer;
- create input remains independent and usable;
- no `ViewModel`, no `Flow`, no coroutines, no DI, no navigation;
- `MainActivity` is unchanged;
- `SAVED_REMINDER_STATE`: restored from existing local persistence through a newly constructed `FileReminderStore` / `ReminderController`;
- `UNSAVED_EDIT_BUFFER`: discarded on Activity recreation.

No architectural semantic change is claimed by Phase 4.

## 11. Phase 4 technical outcome

Provenance label:
MIXED_PROVENANCE

The Phase 4 product / technical result is:

- `ReminderScreen` owns the editing presentation state (`editingId: String?`, `editBuffer: String`) through ordinary `remember(controller)`;
- no `rememberSaveable` is used solely for editing;
- at most one active edit is supported;
- a normal row contains reminder text with Edit and Remove `TextButton`s;
- an editing row contains an `OutlinedTextField` with Save and Cancel `TextButton`s;
- Edit prefills the buffer with the current reminder text and selects the current reminder id;
- Save derives the explicit non-null `activeEditingId` from the active editing row and calls `controller.edit(activeEditingId, editBuffer)`;
- on accepted `true`, Save refreshes `controller.reminders`, exits edit mode, and clears `editBuffer`;
- on normalized-identical accepted `true`, Save also exits edit mode;
- on accepted `false`, the editing state and `editBuffer` are retained;
- on `controller.edit` exception, no success transition occurs;
- Cancel performs no controller mutation and exits editing while clearing `editBuffer`;
- the create input remains independent;
- the `LazyColumn` row key remains the stable `reminder.id`;
- no reorder or sort behavior was introduced.

Phase 4 introduced no `MainActivity` change, no `Reminder` model change, no Phase 4 production `ReminderController` change, no persistence production change, no dependency change, no validator change, no CI change, and no Android identity alignment.
