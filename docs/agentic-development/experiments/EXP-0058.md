### Implementation summary

The Phase-4 Build R1 implementation modified exactly one tracked production file and then created exactly one new untracked experiment record.

Direct implementation actions:

1. **Import addition.** Added one Material3 import line to `ReminderScreen.kt` in its existing import block, placed alphabetically between the existing `Button` and `OutlinedTextField` imports. The line reads:
   ```
   import androidx.compose.material3.Checkbox
   ```
   No other import was added or removed; no Gradle dependency change was introduced (Material3 Checkbox is part of the already-resolved `androidx.compose.material3` artifact set).

2. **Editing-Row Checkbox insertion.** Added a single `Checkbox` composable as the first child of the existing `Row(modifier = Modifier.fillMaxWidth()) { ... }` branch taken when `editingId == reminder.id`. The new Checkbox sits immediately before the existing `OutlinedTextField` (the existing `Edit reminder` field), so the editing row is now `CHECKBOX + EDIT_FIELD + SAVE + CANCEL`. No other element of the editing-Row branch was restructured or moved.

3. **Normal-Row Checkbox insertion.** Added a single `Checkbox` composable as the first child of the existing `Row(modifier = Modifier.fillMaxWidth()) { ... }` `else` branch. The new Checkbox sits immediately before the existing `Text(reminder.text, ...)`, so the normal row is now `CHECKBOX + TEXT + EDIT + REMOVE`. No other element of the normal-Row branch was restructured or moved.

4. **Controlled binding.** Both Checkboxes use the frozen contract:
   ```
   checked = reminder.done
   ```
   `reminder` is the iteration variable already captured by the existing `LazyColumn { items(items = reminders, key = { it.id }) { reminder -> ... } }` block; no new capture or shadowing was introduced.

5. **User-action handler.** Both Checkboxes use the frozen contract:
   ```
   onCheckedChange = { newChecked ->
       val accepted = controller.setDone(reminder.id, newChecked)
       if (accepted) {
           reminders = controller.reminders
       }
   }
   ```
   On normal return AND `accepted == true`, the screen performs `reminders = controller.reminders`. On `accepted == false` (and on any persistence exception that propagates), the screen performs NO success refresh; the existing `reminders` snapshot is retained, and `editingId` / `editBuffer` are not touched.

6. **No second UI authority.** No `MutableState<Boolean>` for done state was created; no additional `remember { mutableStateOf(...) }` was added; no separate `var doneById` map or equivalent was introduced. The single UI authority remains the `ReminderController`-published `reminders` list already surfaced through `var reminders by remember(controller) { mutableStateOf(controller.reminders) }`.

7. **No optimistic publish.** On `onCheckedChange`, the screen does not pre-set a freshly-checked value anywhere. If `controller.setDone` returns `false` or propagates a persistence exception, the visible `checked` of that Checkbox continues to reflect whatever `reminder.done` is in the retained `reminders` snapshot.

8. **Editing interoperability preserved.** Toggling the Checkbox while a row is being edited does NOT clear `editingId`, does NOT modify `editBuffer`, does NOT save `editBuffer`, and does NOT cancel editing. A successful done-state change while editing persists immediately through `setDone`, refreshes `reminders` after accepted success, and leaves the editing surface intact. Later `Save` preserves the current done state through the already-landed controller contract (the existing `controller.edit(activeEditingId, editBuffer)` path is untouched). Later `Cancel` discards only the `editBuffer` (the existing `Cancel` semantics is untouched).

9. **Create semantics preserved.** The `Button(onClick = { ... controller.create(input) ... })` path remains untouched. `Reminder.create` semantics is unchanged: created reminders remain `done=false` per the already-landed domain default.

10. **Remove semantics preserved.** The `TextButton(onClick = { controller.remove(reminder.id); reminders = controller.reminders })` path remains untouched and is identically applicable to done and undone reminders.

11. **Legacy NWR1 render path.** Legacy NWR1 reminders still load through `ReminderController` with `done=false`. With `checked = reminder.done`, those legacy rows initially render unchecked. No new fallback state was added.

12. **Layout non-interference.** No new row, no new column, no new constraint, no new spacer, no new weight, no new modifier was added to either existing `Row` branch. The Checkbox was placed as the leading child of each existing Row without reordering the trailing elements.
