## Implemented helper and test obligations

The new `ReminderTimeUi` uses `java.time` / `java.time.format` and `java.util.Locale`; it imports no Compose or Android framework packages. The source-level API is:

| Method | Contract |
|---|---|
| `pickerMillisToDate(Long): LocalDate` | Convert using UTC calendar fields, not device timezone; reject year outside `1..9999`. |
| `dateToPickerMillis(LocalDate): Long` | Encode UTC midnight; reject year outside `1..9999`. |
| `buildReminderTime(LocalDate, Int, Int): LocalDateTime` | Validate hour `0..23`, minute `0..59`, year `1..9999`; create timezone-free minute-precision local time. |
| `formatReminderTime(LocalDateTime): String` | Validate year and zero seconds/nanoseconds; display `yyyy-MM-dd HH:mm` independently of locale/timezone. |

The display formatter uses `uuuu-MM-dd HH:mm`. For the accepted years `0001..9999`, this yields the same visible four-digit year as the frozen `yyyy-MM-dd HH:mm`. The separate persisted NWR3 literal retains `uuuu-MM-dd'T'HH:mm`; the persistence implementation was not modified in the recorded Write/Edit calls.

The twenty test methods address UTC-midnight conversion, timezone independence, leap-day validity, year boundaries, invalid clock values, minute precision, locale independence, and display-versus-persistence formatting. This describes **source-level coverage** and successful tasks, not completed Compose integration or device acceptance.
