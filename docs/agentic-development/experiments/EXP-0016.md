## Assessment

- **OpenCode observations:** permission rules are order-sensitive in effective runtime behavior. Static inspection alone was insufficient; fresh-process execution was necessary. Exact-deny and exact-allow combinations can behave differently from an intuitive glob interpretation, so the effective matcher must be validated empirically.
- **Model observations:** MiniMax M3 followed narrow mutation scope and hard-stop behavior reliably in these stages. It was much less reliable at response-integrity constraints, exact evidence counting, and separating direct observation from matcher-mechanism inference.
- **Task-specification observations:** splitting B1V2 into allow-side and denial-side sessions kept each fresh ordinary process inside the permanent agent's `steps: 20` budget and produced complete evidence.
- **Environment observations:** OpenCode denial results directly report that the tool call was prevented before shell execution but do not surface the exact winning permission rule.
- **Direct observations:**
  - final corrected `nudge-audit.md` has 58 lines;
  - bare, cached, and path-scoped required forms execute;
  - both exact tracked-tree commands execute;
  - all eight prohibited forms are denied before shell execution;
  - the working tree remained exactly one modified tracked file during runtime validation;
  - no stage staged, committed, pushed, installed dependencies, used network commands, or inspected raw private session files from inside OpenCode.
- **Inferences:**
  - the B1R ordering is responsible for restoring the bare commands; this is strongly supported by the before/after fresh-process behavior but the internal matcher algorithm remains unavailable.
- **Corroborating evidence:**
  - B1V2-A's successful bare commands corroborate the purpose of the B1R reordering.
  - B1V2-B's eight denials corroborate that the correction did not reopen the broad argument surface.
- **Lessons supported by this experiment:**
  - every permanent permission rewrite requires fresh-process runtime probes;
  - allow and denial behavior should be split when the permanent agent's action budget is small;
  - matcher-rule attribution must not be claimed unless surfaced directly;
  - response-integrity claims require transcript review rather than agent self-report.
- **Candidate rule changes:** record in future governance that ordered OpenCode permission rules must be treated as empirically validated behavior, not inferred glob semantics.
- **Candidate validation changes:** retain the B1V2-A and B1V2-B probe sets as the reusable regression baseline for future `nudge-audit` permission changes.
- **Candidate reusable skills or commands:** a future bounded harness-validation procedure may encode the two-session allow/deny probe sequence after repeated independent use.
