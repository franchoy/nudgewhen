### setDone control flow (directly implemented)

- Missing id: returns `false`; no save; no state change.
- Existing id, same `done` value: returns `true`; no save; no state change.
- Existing id, different `done` value: derive candidate from current list; replace only the same-index target via `state[index].copy(done = done)`; preserve id, text, index, neighbors, and order; call `store.save(candidate)` exactly once; publish `state = candidate` only after save returns successfully; return `true`.
- If `save` throws: exception is not caught / wrapped; no Boolean is produced; `state` remains unchanged.
- `idGenerator` is never invoked on any `setDone` path. Attempt-1 D_05 exercised the changed-state and missing-id paths but did not exercise the same-state path; R1 bounded correction modified D_05 to also exercise the same-state path (`controller.setDone("a", true)` invoked a second time after the first call already set `a.done = true`); the corrected D_05 was directly revalidated with `./gradlew --offline :app:testDebugUnitTest --rerun-tasks --tests "io.github.franchoy.nudgewhen.domain.ReminderControllerTest"` (BUILD SUCCESSFUL; XML `tests="51" skipped="0" failures="0" errors="0"`), and `assertEquals(0, idCalls)` held across changed-state, same-state, and missing-id invocations.
